# Altasreef AI Tutor

**Grounded, multilingual error explanations for Quranic Arabic morphology.**
Submission for the Islamic AI Challenge (islamicaich.org), Track 3 — "Interactive
Experiences & Learning Journeys for Islam". Team Altasreef.

## What this is

[Altasreef](https://morphology.haqnawaz.org) is a live Arabic morphology (علم الصرف)
learning platform that tests students on real Quranic verses, not invented textbook
sentences. When a student answers a question wrong, this project adds a grounded
explanation of *why* the correct answer is correct — the feature built specifically
during this challenge's Oct 4–6 window.

**Baseline disclosure, per the challenge's own rule:** the Altasreef platform itself
(evaluation engine, Quran tagging pipeline, multilingual UI, certification levels) is
pre-existing work, live since before October 4. Everything in this repository —
the rule database, the matcher, the `/explain` and `/ilal` APIs, and the demo page —
is new work built during the Oct 4–6 window and is the only part offered for judging.

## Architecture: retrieval, not generation

**The explanation text is never generated by an LLM.** Given a wrong answer
(`dimension`, `correct_value`, `given_value`, plus the real word/root/verse it came
from), the system looks up a pre-authored template by exact match
(`app/matcher.py` → `rules/wrong_answer_rules.json`) and fills in the specific word,
root, and reference. If no rule matches, **it says so explicitly and abstains** —
there is no fallback to generation anywhere in the code path.

This is a direct answer to the challenge's own stated principle on reliability
(المرجعية والحزمة العلمية والبيانات): *"عند غياب المرجع الكافي... تكون الأولوية
للامتناع أو التحفظ... لا لتوليد إجابة غير موثقة"* — prefer abstention over
generating an undocumented answer. A pure lookup system has zero hallucination
surface by construction.

We also tested the alternative (a live, constrained LLM call per wrong answer —
see `research/test_explanations.py` and `research/pilot_dataset.json`, kept in this
repo as the documented reasoning trail for *why* we didn't ship that approach) before
deciding the retrieval-only design was both safer and more buildable in three days.

### Two complementary explanation modes

1. **`/explain`** — why is dimension *X* equal to value *A*, not the value the student
   gave? (`app/matcher.py`, `rules/wrong_answer_rules.json`). Rules are prioritized by
   real frequency: we pulled live production data (5,215 real answer rows) and authored
   rules for the ~25 (dimension, correct, given) patterns that cover over 80% of all
   real wrong answers ever recorded, rather than attempting exhaustive coverage.

2. **`/ilal`** — a second, different question: given a correct form, *how* is it
   derived step-by-step through إعلال (vowel/letter transformation)? E.g. why قَوَلَ
   becomes قَالَ. (`app/taaleelat_rules.py`, ported from a sibling project, currently
   covering اجوف واوی roots in باب نصر for ماضی/مضارع/امر.)

### A finding worth being transparent about, not hiding

The single most common "wrong answer" in the live data (145 of the top 1,627 sampled
wrong answers) was `number: تثنیہ جمع ← جمع` on 1st-person-plural verbs like قُتِلۡنَا.
Arabic's متکلم plural ending (ـنَا) genuinely doesn't distinguish "we two" from "we
many" — so a student answering plain جمع isn't making a grammar mistake; the
underlying data model just records a combined placeholder value that the scoring
logic compares strictly. Rather than author a rule that defends this as if the
student erred, that rule explicitly discloses it as a known system limitation
(see the `is_system_limitation_disclosure` flag in the rule data and the matcher).
This is, deliberately, the AI-transparency principle (الشفافية) applied to our own
system's imperfection rather than just to AI-generated text.

## Repo boundary — what's public vs. what stays private

The production Altasreef backend (auth, user database, the full evaluation engine,
the full Quran tagging corpus) stays closed-source — it's a live service with real
user data, and publishing it isn't something we have the right to do, nor is it what
this challenge needs. This repository is a **standalone, independent service**:

- No dependency on the production codebase or database.
- No real user data anywhere.
- `data/surah_114_sample.json` — a small, fully-tagged, self-contained slice of our
  tagging pipeline's *output* (Surah 114, every word tagged, zero redaction needed
  since nothing here is sensitive) — included so the grounding data behind the
  explanations is independently inspectable, without publishing the full ~99,000-word
  corpus.
- `research/pilot_dataset.json` — a redacted sample of real (anonymized) wrong-answer
  patterns used to prioritize rule authoring. No user identifiers of any kind.

## Running it locally

```bash
cd app
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

Then open `demo/index.html` directly in a browser (set
`window.ALTASREEF_API_BASE = "http://127.0.0.1:8000"` before the script runs if not
using the default port), or deploy `app/` to Render and `demo/` to Netlify/Cloudflare
Pages for a public link.

## API

```
GET  /sample            -- a handful of real curated demo scenarios
POST /explain            {dim, correct_value, given_value, word, root, ref, lang}
                          -> {matched, rule_id, tier_a, is_system_limitation_disclosure}
                          or {matched: false, reason: "no_rule" | "not_actually_wrong"}
POST /ilal                {root_word, baab_name, tense}
                          -> {matched, rows: [{person_reference, final_form, ilal_chain}]}
                          or {matched: false, reason: "unsupported_combination"}
```
